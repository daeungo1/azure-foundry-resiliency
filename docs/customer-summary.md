## 제안 요약

Global Standard(PayGo)를 사용하는 글로벌 Agent에 대해 다중 구독·멀티 리전의 모델 호출 BP를 권장합니다.
핵심은 quota와 endpoint 장애 도메인을 구분하고,
정상적인 동일 모델 후보를 우선 사용하면서 승인된 대체 모델까지 전환 경로를 확보하는 것입니다.

Region01~RegionN의 사용자 인접 gateway에서 요청을 처리하고,
구독별 quota 예산·endpoint별 circuit·모델별 품질 승인을 공통 정책으로 관리합니다.
응답 모델 변경 여부를 명확히 기록하여 서비스 연속성과 업무 품질을 함께 관리합니다.
[BP 구성도와 호출 흐름](../README.md#권장-bp-아키텍처)을 기준으로 고객 환경에 적용합니다.

## 429에 대한 해석

설정된 quota 미만의 사용량에서도 공유 용량 풀의 일시적 압력, effective rate limit 조정,
요청 token 추정, burst 등의 이유로 429가 발생할 수 있습니다.
`x-ratelimit-remaining-requests`, `x-ratelimit-remaining-tokens`와 reset·Retry-After 정보를 활용하여
선제 admission, 제한된 재시도, circuit breaker와 승인된 후보 전환을 수행합니다.

2026년 도입된 quota 체계에 편입된 모델은 동일 구독의 모든 리전에서
같은 모델·버전의 Global Standard quota를 공유합니다.
따라서 멀티 리전만으로 quota가 늘어나거나 shared-pool throttling이 반드시 사라진다고
보장할 수 없습니다. 모델별 실제 quota `Scope`를 확인해야 합니다.

## TTFT 관리

리전 거리만으로 순서를 고정하지 않고, 안전성 조건을 통과한 후보를 실제 Streaming TTFT로 그룹화합니다.
사용자 접점·업무·모델·버전·입력 조건마다 다음 구성을 권장합니다.

| 그룹 | 호출 정책 |
|------|-----------|
| Primary | TTFT 목표를 만족하는 동일 모델의 동급 후보에 headroom·동시성 기반 분산 |
| Resilience | 429·일시 장애 시 다른 승인 endpoint의 동일 모델로 시간 예산 내 전환 |
| Approved fallback | 업무 품질·안전성을 승인한 타 모델만 명시적 opt-in으로 사용 |

구독은 별도 quota 확보의 기준이지 빠른 TTFT의 보장이 아닙니다.
빠르다는 이유로 데이터 처리 범위나 content safety를 완화하지 않으며, 안전성 거절을 다른 모델로 우회하지 않습니다.

사용자 인접 진입점과 지역별 Agent를 사용하고 불필요한 대륙 간 왕복을 줄입니다.
연결·인증 token 재사용, prompt 및 RAG 크기 관리, 지원되는 prompt caching,
스트리밍 전달과 짧은 bounded queue를 함께 적용합니다.
첫 텍스트 이전의 장애 전환은 시간 예산 안에서만 수행하며,
첫 텍스트 이후에는 자동 재생으로 중복 응답이나 tool 부작용을 만들지 않습니다.

Global Standard의 리소스 리전은 추론 처리 리전이나 일정한 TTFT를 보장하지 않습니다.
국가별 실제 Agent 경로에서 TTFT·TBT·전체 응답 시간·실패율을 함께 검증해야 합니다.
첫 non-empty 텍스트 기준의 SSE 검증은 구현되어 있습니다.
현재 지역 선호도는 정적 설정이며 실측 TTFT 기반 자동 그룹 갱신은 추가 운영 구성입니다.
모의 장애 결과를 실제 리전 순위로 사용하지 않습니다.
[그룹 기준과 공식 BP 근거](latency.md)를 바탕으로 실측 후 승인한 순서부터 반영합니다.

## 적용 효과 참고 지표

단일 endpoint와 사전 계측 profile·장애 전환을 비교한 TTFT·응답 성공률은
[README의 전후 비교표](../README.md#적용-전후-ttft와-응답-성공률)에 함께 정리했습니다.
해당 표는 지연을 통제한 로컬 SDK SSE의 측정값이며 실제 Azure 운영 TTFT와 구분합니다.

| 적용 항목 | 대조 구성의 성공 응답 | BP 적용 구성의 성공 응답 | 고객 관점의 효과 |
|-----------|----------------------|-------------------------|------------------|
| 모델 전체 429 | 동일 모델만 사용: 0/80 | 승인 모델 fallback: 80/80 | 공통 throttling 시 전환 경로 확보 |
| 모델 전체 503 | 동일 모델만 사용: 0/80 | 승인 모델 fallback: 80/80 | 모델 단위 장애의 사용자 영향 완화 |
| 요청 예산 소진 | 단일 구독·동일 모델: 8/80 | 두 구독·동일 모델: 80/80 | 품질 변경 없이 별도 quota 활용 |

한 구독의 429·503 및 요청/토큰 headroom 부족의 네 조건에서는 합계 640/640 응답을 확인했고,
정상 구독의 동일 모델로 연속 처리했습니다.
cooldown을 재사용한 모델 fallback은 최초 요청의 5회 시도 이후 후속 요청을 각각 1회 시도로 처리했습니다.

참고 수치는 2026-10-20(KST)에 재실행한 네 모델·4개 지역·HTTP/SSE의 통제된 장애 주입 검증에서 집계했으며,
두 구독 비교는 구독별 quota pool을 별도로 관리하는 조건입니다.
실제 적용 시에는 동일 지표를 고객의 운영 SLO·업무 품질·비용과 함께 측정합니다.
[측정 조건과 원시 결과](../README.md#검증-근거)를 함께 제공합니다.

## 적용 단계

1. 모델별 실제 quota Scope·배포 버전·데이터 처리 범위를 확인합니다.
2. 운영 identity의 각 target resource 호출 권한과 네트워크 접근을 구성합니다.
3. 헤더 기반 admission·동일 모델 전환을 먼저 적용하고, 업무 평가를 통과한 fallback을 추가합니다.
4. 사용자 TTFT, 최종 성공률, 최종 429 노출률, 모델 변경률과 성공 요청당 비용으로 효과를 확인합니다.
5. 제한된 트래픽부터 확대하고 장애·복구 시험으로 정책을 조정합니다.

여러 replica에는 공유 예산과 사용자별 공정성을 적용합니다.
별도 quota와 글로벌 공급 용량은 구분하고, 모든 후보가 제한되는 상황의 업무별 처리 정책을 함께 정의합니다.
